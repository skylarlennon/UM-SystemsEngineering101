SRR — System Requirements Review

Decision: requirements set is complete/consistent; ready to allocate.
Show: stakeholder needs → system “shall”s, verification methods (T/D/I/A), risk & traceability.
Where it sits: establishes/locks the functional baseline early; baselines progress is managed with a specification tree and configuration management discipline. 

Automotive Systems Engineering …

SFR / SDR — System Functional/Definition Review

Decision: functions decomposed and allocated; interfaces sketched.
Show: function tree, early ICDs, architecture options, performance budgets.
Where it sits: functional baseline leads into PDR; decomposition is explicitly emphasized before design lock. 

Automotive Systems Engineering …

PDR — Preliminary Design Review

Decision: choose/confirm architecture; establish the allocated baseline (subsystem performance requirements).
Show: trades & rationale, preliminary analyses/sims, ICD snapshots, verification strategy.
Where it sits: PDR = event-driven technical review that locks the functional→allocated baselines; part of the program’s specification tree/CM plan. 

Automotive Systems Engineering …

CDR — Critical Design Review

Decision: design is buildable/testable; establish the product baseline (drawings, BoMs, models).
Show: finalized schematics/CAD, tolerances, updated analyses, safety/FMEA, build & test plans.
Where it sits: CDR = event-driven technical review that locks the product baseline. 

Automotive Systems Engineering …

IDR / Peer Design Reviews (component/subsystem)

Decision: lower-level designs meet their allocated requirements; ready for fab/test.
Show: component specs vs. allocation, analysis & test plans, peer review findings.
Where it sits: called out in the Requirements & Testing flow alongside PDR/CDR/PRR as standard design/peer reviews. 

Automotive Systems Engineering …

TRR — Test Readiness Review (when you formalize it for track/bench/solar-array tests)

Decision: procedures, configuration, hazards, entry/exit criteria are ready to execute.
Show: requirement→test mapping, fixtures/instrumentation, dry-run results.
Where it sits: part of the “Integration, test, and verification planning and procedure generation” stream that precedes formal system/subsystem testing. 

Automotive Systems Engineering …

PRR — Production Readiness Review (or pilot-build readiness for student teams)

Decision: process, fixtures, and suppliers (if any) are capable to build at quality/takt; approve pilot/line.
Show: control plans, PFMEA/GR&R, pilot build results, coverage on end-of-line tests.
Where it sits: explicitly listed with PDR/CDR in the SAE flow; downstream of verification/validation planning. 

Automotive Systems Engineering …

PPAP / Run-at-Rate (automotive production milestone)

Decision: evidence that design & manufacturing processes can produce conforming parts at rate.
Show: PSW, DFMEA/PFMEA, process flow, control plan, MSA, initial capability, lab results.
Where it sits: treated as a major milestone gating launch in the SAE project-management guide.
